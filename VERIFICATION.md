## Legacy AuditStamp source compatibility (8 October 2026)

The opt-in Kafka source adapter was tested with the original 0.2.0 wheel in Actions
1.3.0, GMS 1.3.0.1, and retained real startup records generated by official SystemUpdate
1.2.0. The current initializer was 1.3.0.1. No version, upstream decoder or registry
changes were applied, and Kafka history was not deleted.

The unchanged decoder still failed on 220 retained legacy records. With the adapter,
both a compliance worker and a printing worker used fresh groups and `earliest`,
translated those records, and consumed all history. Final offsets reached 667 versioned
MCL records and 37 PlatformEvents with zero lag for both groups. New GraphQL and SDK tag
changes assigned forms; ownership assigned the Minimum Metadata form and initialized
its status; a subsequent description change was processed successfully. No Avro,
Kafka-consume or worker exceptions appeared.

Seven focused regressions passed inside Actions 1.3.0 and in the development environment.
They cover binary Avro named-union conversion, unchanged current-event payloads, input
preservation, unknown-namespace failures, invalid-record failures, plugin loading and
offset acknowledgments. The complete repository gate passed 52 tests, Ruff checks,
wheel build and dependency checks using the pinned 1.6.0.16 SDK. A standalone copy of
the adapter also loaded from the existing Actions 1.3 import path without replacing
the wheel or changing `PYTHONPATH`.

[Compatibility result manifest](evidence/auditstamp-source-compat-results.json).

This verifies the fix for the observed namespace mismatch in the isolated reproduction.
The exact company startup producer, company registry response, authentication and MSK
configuration remain unverified. Other schema incompatibilities are not suppressed.

## Limits

GMS 1.3 rejects conditional JSON Patch `test` operations. The Action reads immediately before its
targeted property patch, but a simultaneous write to the same property between those operations
can be overwritten. Strict atomic initialization is not supported. See [DESIGN.md](DESIGN.md).

Live tests use actual GMS, Kafka, and the Actions worker. The local GMS has authentication disabled.
Company authentication, authorization, AWS MSK IAM, Kafka ACLs, custom GMS patches, production
workloads, outage recovery, high availability, and simultaneous independent writers were not tested.
Windows checks cover installation and unit/build behavior, not a Windows-to-Kafka integration run.
The transitive Authlib deprecation warning did not affect the completed checks.

The new rules were exercised through real API mutations and Kafka events, without a browser test.
The earlier tag-only release's results remain in
[evidence/gms13-cli16-live-results.json](evidence/gms13-cli16-live-results.json) and
[evidence/gms13-cli16-versions.json](evidence/gms13-cli16-versions.json).
